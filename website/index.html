Introduction

Reproducing a machine-learning paper requires more than generating plausible code. An agent must recover the target claim, respect the experimental contract, complete every required stage, and deliver artifacts whose reported metric can be independently checked. ReproBoundary evaluates this end-to-end capability across 47 frozen paper-to-code tasks.

Each task fixes the source repository and revision, data scope, required stages, compute budget, target metric, reference value, and evaluator before the run begins. Twenty tasks retain the paper-selected experimental scale; 27 reduce training, search, or repetition while keeping the complete target evaluation set.

Scope. Each task reproduces one selected result under a fixed resource limit. It does not reproduce every result or support every conclusion in the source paper.

Construction Pipeline

The benchmark is built as a traceable chain from one paper-reported result to a frozen task, a controlled run, and an independent check.

01

Select a target result

Freeze one concrete experiment, paper-reported reference value, public source repository, and exact code revision.

02

Define the contract

Record the data scope, required stages, target metric, evaluator, and time, compute, memory, and storage limits.

03

Run the agents

Execute every task with nine model-agent settings, producing 423 indexed trajectories across the 47-task pool.

04

Release and verify

Separate lightweight code from compressed logs, redact sensitive text, index file hashes, and provide deterministic integrity checks.

Task Taxonomy

Tasks are organized along three explicit dimensions instead of being reduced to a single difficulty label.

Experimental scale

20 paper-scale tasks retain the experiment size selected from the paper. 27 resource-bounded tasks reduce training, search, or repeated work while retaining the complete target evaluation set.

Research domain

The pool spans 15 domains, including language models, multimodal learning, computer vision, reasoning, safety, reinforcement learning, time series, graph learning, retrieval, and scientific machine learning.

Verification contract

Every task binds one target metric to its dataset, required outputs, evaluator source, evaluator version, and expected result format.

Evaluation Framework

Evaluation Protocol

ReproBoundary does not treat a plausible report or a matching number as sufficient evidence of reproduction.

Execution

Did the run complete every stage required by the frozen task specification?

Delivery

Are the expected outputs, provenance records, and supporting artifacts present and traceable?

Metric replay

Can the task-specific evaluator recompute the submitted target metric from the required artifacts?

Agreement

Does the recomputed metric agree with the submitted value under the task's declared comparison rule?

Important. Metric agreement confirms a number; it does not by itself prove that every required experimental stage was completed. Process evidence and metric evidence remain separate.

Data and Verification

GitHub hosts the lightweight task definitions, evaluator records, protocol templates, and verification code. Hugging Face hosts 423 cleaned, compressed execution logs with a central provenance index and SHA-256 fingerprints.

git clone https://github.com/ReproBoundary/ReproBoundary.git

# verification OK: tasks=47 evaluators=47 trajectory_records=423 bundled_logs=0

Evidence boundary. The logs support chronology, tool-use, failure, and release-integrity analysis. They do not include checkpoints, predictions, model weights, or training states and cannot by themselves replay most scientific metrics.
